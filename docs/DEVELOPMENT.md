# 开发规范

## 核心架构
- Kotlin + Jetpack Compose + Material 3；应用独立在手机运行。
- 无电脑、ADB、Root 或 Shizuku 依赖；最低 Android 11 / API 30，通过 Gradle minSdk 固定为 30。
- 实现设备检测、内置应用清单、官方下载入口、单应用可信下载器与系统安装确认。
- 不支持也不计划开发清单导入/导出、自动批量安装、自动失败重试；应用逐项下载、由用户逐项确认安装。

## 下载模块（V0.3）
1. 默认策略为 **smart**：官方 GitHub Release 元数据提供 SHA-256 时，可并发探测 GitHub 原始 URL 与可选 HTTPS 前缀镜像并按照响应延迟排序，然后逐项尝试。响应延迟仅供候选排序，不代表实际下载吞吐；已明确选择镜像时优先该源，失败回退官方源。
2. 用户可在手机端选自动、官方、预置社区镜像或自定义 HTTPS 镜像。预设 GHFast / GH-Proxy / LLKK / GHProxy.net，HiWiki 源列表 https://git.hiwiki.org/zh-CN/mirrors 为参考入口而非声称同步实时节点。自定义 HTTPS 源校验域名格式并在本地保存，支持删除（最多 12 个）。
3. 下载任务支持 HTTP/SOCKS5 代理，但 **默认关闭**；仅在用户主动启用后生效，不自动修改全局 VPN。
4. APK 必须核验来源；有官方 SHA-256 时必须校验完整安装包；缺少完整摘要时镜像禁止下载，只允许官方文件直连，并由 Android 安装器进行基本格式/签名校验。
5. 已安装应用升级时校验签名兼容性，避免被替换为不受信任包。
6. 测试覆盖下载进度、失败提示、单任务状态、来源切换和校验失败；不添加自动失败重试或批量安装。取消/断点续传尚未实现。
7. 不将 FlClash 安装作为使用下载器的前置条件。
8. 应用清单及默认配置内置到 APK，离线也能查看。

## Android 平台限制
- 普通 App 不能绕过 Package Installer 实现静默安装；用户必须明确确认系统安装界面。
- 输入法启用及默认选择由用户在系统设置中完成；不得宣称后台更改成功。
- 权限、通知、电池优化和系统时间等受保护设置只做检查和设置引导。
- GhostLock 为高风险工具，仅允许作为明确提示的外部项目入口，不进行自动利用/提权。

## 兼容与云端验证
- CI 构建后必须通过 Android 11 (API 30) 和 Android 15 (API 35) 的实际模拟器安装/启动流程。移动端不需要计算机，CI 里的 ADB 仅用于自动化测试。
- 测试覆盖默认智能模式、预置源选择与持久化、自定义 HTTPS 地址添加与持久化、官方直连下载、SHA-256 校验与实际系统安装。
- 尚未覆盖中国大陆三大运营商真实链路、实际镜像网络加速、真实 SOCKS5/HTTP 代理端到端链路；此类项目不得虚报通过。

## 开发验收
- Kotlin 编译、清单解析、用户勾选状态保存；通过真实 Android 模拟器安装、启动与操作检查。
- 已配置下载源不可达时明确报错而非伪造成功。
- 官方 SHA-256 存在时必须逐字节验证；镜像无可信摘要时禁止回退。Android 系统安装器负责执行签名一致性检查；应用层证书可信链验证尚待实现。
- 代理默认处于关闭状态。
- 最终发布 APK 前开展真实设备安装测试和第三方软件授权审核。
